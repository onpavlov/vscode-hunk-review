# hunk-review: интеграция VS Code с hunk.dev — дизайн

Дата: 2026-09-09
Статус: черновик на ревью

## Проблема

hunk — терминальный просмотрщик диффов с инлайновыми комментариями. Мы хотим
оставлять комментарии к диффу из VS Code: с ховер-подсказками, тредами и
отправкой в живую hunk-сессию, где их может прочитать кодинг-агент через
`hunk session *`.

## Решение в двух словах

Расширение hunk-review показывает незакоммиченные изменения репозитория в
нативных diff-редакторах VS Code, позволяет комментировать изменённые строки
через Comments API, хранит комментарии локально и отправляет их в живую
hunk-сессию (создавая фоновую сессию в скрытом терминале по требованию).
Взаимодействие с hunk — только через документированный CLI (`hunk session *`).

## Принятые решения

| Вопрос | Решение |
|---|---|
| Сценарий | Автономный в VS Code, без обязательного TUI |
| UI диффа | Нативные diff-редакторы VS Code + Comments API |
| Объём ревью | Незакоммиченные изменения: рабочее дерево + staging |
| Комментарии без сессии | Store-and-forward, подтверждение отправки пользователем |
| Фоновая сессия | Скрытый терминал (`createTerminal({ hideFromUser: true })`) с `hunk diff` |
| Хранение комментариев | Файл `.hunk-review/comments.json` в репозитории |
| Транспорт | CLI-подпроцессы (`hunk session ...`), без WebSocket/MCP |
| Автостоп сессии | Рабочее дерево стало чистым → сессия останавливается |

## Архитектура

### Компоненты

1. **DiffService** — источники диффа. Через API встроенного Git-расширения
   (`vscode.git`) получает список изменённых файлов и строки хунков рабочего
   дерева и staging. Не читает `git` сам; если Git-расширение недоступно —
   деградирует с ошибкой «Git not available».
2. **HunkCli** — единственная точка вызова hunk. Обёртка над
   `child_process.execFile` с таймаутами:
   - `hunk session list` — обнаружение сессий (парсинг вывода; формат JSON
     уточняется флагом `--json`, при отсутствии — разбор текстового вывода);
   - `hunk session review --repo <root> --json` — структура хунков сессии;
   - `hunk session comment apply --repo <root> --stdin` — батч-отправка;
   - `hunk session comment list --repo <root>` — сверка отправленных;
   - `hunk session reload --repo .` — после изменения рабочего дерева.
3. **SessionManager** — жизненный цикл фоновой сессии:
   - запуск: скрытый терминал с `hunk diff` в корне репозитория;
   - ожидание регистрации: опрос `hunk session list` до появления сессии
     репозитория (таймаут 10 с, потом тост с ошибкой);
   - остановка: `terminal.dispose()` — TUI завершается, сессия снимается
     с демона;
   - автостоп: подписка на события Git-расширения (`onDidChangeState` /
     опрос diff). Если рабочий diff пуст (закоммичено, отменено, засташено) —
     сессия останавливается, пользователь получает тост с пояснением.
4. **CommentStore** — `.hunk-review/comments.json` в корне репозитория:

   ```json
   {
     "version": 1,
     "comments": [
       {
         "id": "uuid",
         "filePath": "src/App.tsx",
         "target": { "newLine": 103 },
         "summary": "Текст комментария",
         "status": "pending",
         "sessionCommentId": null
       }
     ]
   }
   ```

   `target` — ровно один вариант: `newLine` или `oldLine`.
   `status`: `pending` → `sent` (после успешного `comment apply`;
   `sessionCommentId` — id в сессии).
5. **CommentSync** — двусторонняя синхронизация комментариев с живой сессией:
   - пока сессия активна, опрос `hunk session comment list --repo <root> --type all`
     (раз в 5 с);
   - комментарии из hunk отображаются в VS Code:
     - комментарий агента на строке, где есть наш тред → добавляется **reply**
       в этот тред;
     - комментарий без нашего треда → отдельный read-only тред под строкой
       (автор подписан как «hunk agent»);
   - комментарии, созданные человеком в TUI (`human note`), импортируются
     так же и остаются read-only;
   - при остановке сессии импортированные комментарии остаются в VS Code
     как read-only история.
6. **CommentBridge (VS Code Comments API)** — контроллер
   `hunk-review.comments`:
   - треды на изменённых строках diff-редактора;
   - создание комментария: клик по декорации «+» на выделении диапазона или
     ховер «Добавить комментарий» на изменённой строке;
   - рендер статуса (`pending`/`sent`/`stale`), редактирование и удаление
     `pending`-комментариев; `sent`- и импортированные комментарии
     read-only в VS Code (истина — в hunk-сессии).
7. **Decorations** — подсветка строк с комментариями в diff-редакторе
   (`Decoration` с гуттер-иконкой).

### Потоки данных

**Добавление комментария:** строка diff → CommentBridge → CommentStore
(статус `pending`) → декорация обновлена.

**Отправка агенту (кнопка/команда `sendComments`):**
1. Если pending нет — тост «Нечего отправлять».
2. `SessionManager.ensureSession()`: сессия есть — ок; нет — запуск фоновой
   и ожидание регистрации.
3. Формирование батча и `comment apply --stdin`; валидация hunk применяет
   весь батч атомарно. При ошибке валидации — тост с текстом ошибки, статусы
   не меняются (комментарии остаются `pending`).
4. Успех → статусы `sent`, `sessionCommentId` из ответа; тост «N комментариев
   отправлено, hunk-сессия работает в фоне».
5. Пользователь/агент работают в hunk; агент читает комментарии штатно через
   `hunk session *` (скилл hunk уже это умеет). Ответы агента подхватываются
   CommentSync и появляются в VS Code в треде исходного комментария.

**Остановка:** команда `stopSession` или автостоп → dispose терминала →
`pending`-комментарии остаются в сторе.

**Ревью открыто, сессии нет:** комментарии видны из стора; кнопка
«Отправить» предлагает создать фоновую сессию.

## UI

- Status bar: `$(eye) hunk: 2 pending · session on/off`. Клик → меню:
  Открыть ревью / Отправить комментарии агенту / Остановить сессию /
  Показать терминал сессии.
- Команды (ID префикс `hunk-review.`): `openDiff`, `sendComments`,
  `stopSession`, `showSessionTerminal`.

## Обработка ошибок

- hunk не установлен → тост с подсказкой установки, отправка заблокирована.
- Демон не запущен (`session list` падает) → расширение считает сессий
  ноль; запуск фоновой сессии включает и демон (hunk поднимает его сам),
  если нет — тост с ошибкой.
- Комментарий указывает на строку, которой больше нет в диффе → при отправке
  hunk отклонит батч; расширение помечает такие комментарии как `stale`
  и предлагает удалить или перепривязать.
- Несколько живых сессий одного репо → расширение берёт первую из
  `session list` и показывает это в тосте.

## Тестирование

- Unit: парсинг вывода `session list`/`review --json` (фикстуры), маппинг
  батча, мутации CommentStore, логика автостопа (подмена состояния git).
- Интеграционные: mock-исполняемый файл `hunk` (скрипт в PATH тестов),
  сквозной сценарий «комментарий → отправка → sent».
- Ручной smoke: реальный `hunk` + агент.

## Ограничения и риски

- Формат вывода `session list` и `comment apply` без `--json` может быть
  нестабильным; проверяется мини-спайком на первом шаге реализации.
- Автостоп опирается на события Git-расширения; редкие состояния (например,
  `git stash` из внешнего процесса) покрываются опросом при активации
  окна и при команде отправки.
- `.hunk-review/comments.json` — файл в репозитории; `.gitignore`-запись
  добавляется расширением при первом создании (если глобального игнора нет).
- Headless-создание сессии через демон hunk не поддерживается; фоновая
  сессия возможна только через скрытый PTY-терминал VS Code.

## Вне скоупа (позже)

- Ревью веток/коммитов (`hunk show`, `hunk diff from to`).
- Настройка автосинхронизации с живой сессией (частота опроса, направления).
